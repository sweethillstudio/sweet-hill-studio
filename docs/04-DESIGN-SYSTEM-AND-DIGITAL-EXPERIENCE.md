# 01. DESIGN NORTH STAR

## CONTEMPORARY EDITORIAL WONDER

The website should feel like:

- a contemporary publishing house
- a beautiful digital editorial environment
- a carefully curated cultural brand
- a premium commerce experience
- a place visitors can explore

It should not feel like:

- a generic children's website
- a generic WordPress theme
- a template-based online bookstore
- a conventional religious bookstore
- a technology demo
- an agency portfolio pretending to be a publisher
- an AI-generated site

The desired balance is:

**EDITORIAL × CULTURE × WONDER × COMMERCE × TECHNOLOGY**

No single element should dominate.

# 02. BRAND EXPERIENCE PRINCIPLES

## 02.1 Quiet confidence

The interface should not shout.

Use:

- strong composition
- restrained typography
- excellent imagery
- purposeful motion
- whitespace
- clear hierarchy

Avoid visual noise.

## 02.2 Intelligence

The site should appear carefully thought through.

Every visual element should have a reason.

## 02.3 Wonder

Wonder should come from the books, stories, characters and worlds.

The UI does not need to become childish to create delight.

## 02.4 Cultural confidence

Indic and Vaiṣṇava subject matter should be presented with genuine respect and visual intelligence.

Avoid decorative clichés that reduce culture to visual motifs.

## 02.5 Premium

The user should feel that the books are considered objects, not commodity products.

## 02.6 Human

The people who make the books should remain visible.

The site should feel authored.

## 02.7 Future-facing

The interface should feel appropriate to the late 2020s rather than reproducing familiar 2015–2020 WordPress aesthetics.

# 03. THE "NOT A KIDS WEBSITE" RULE

The child-facing emotional experience should be created principally through:

- illustration
- storytelling
- characters
- visual worlds
- colour
- motion
- humour
- curiosity

The interface should remain mature enough for:

- parents
- grandparents
- educators
- booksellers
- institutions
- international partners

### Avoid

- pastel-everything
- cartoon clouds
- childish menus
- excessive stickers
- rainbow UI
- nursery typography
- excessive bubbles
- excessive rounded cards
- generic children's clipart
- toy-store aesthetics
- visual clutter

### Allowed

- playful transitions
- charming micro-interactions
- unusual editorial compositions
- character moments
- expressive illustration
- subtle surprises
- story-driven motion

The site should be **delightful without becoming juvenile**.

# 09. LAYOUT SYSTEM

## 09.1 Grid

Use a flexible editorial grid rather than a rigid ecommerce grid.

Initial desktop concept:

- 12-column grid
- generous outer margins
- responsive column relationships
- consistent gutters
- maximum content width
- full-bleed exception zones

## 09.2 Editorial asymmetry

Not every section should be centered.

Use:

- left-aligned type
- right-hand image
- offset blocks
- overlapping layers
- large empty fields
- image cropping
- edge alignment

But retain an underlying grid.

Asymmetry should feel deliberate, not chaotic.

## 09.3 Full-bleed moments

Reserve full viewport sections for:

- hero
- major story moment
- series introduction
- cinematic transition
- major forthcoming release

Do not make every section full-screen.

---

# 10. TYPOGRAPHY

Typography is one of the primary mechanisms for making the site feel premium.

## 10.1 Primary editorial family

Choose a refined serif with:

- excellent display characteristics
- multiple weights
- italic support
- strong punctuation
- good Unicode support
- reliable diacritics

## 10.2 Interface family

Choose a modern sans-serif with:

- excellent screen rendering
- tabular numerals
- strong small-size performance
- extensive weight range
- good international support

## 10.3 Sanskrit / IAST

Typography must explicitly test:

- ā
- ī
- ū
- ṛ
- ṝ
- ṃ
- ṅ
- ñ
- ṭ
- ḍ
- ṇ
- ś
- ṣ

and other relevant characters.

Do not compromise official Sanskrit titles because of font limitations.

## 10.4 Devanāgarī

Use a high-quality Unicode Devanāgarī family where required.

The system should support language-specific font stacks.

## 10.5 Typographic behaviour

Use large editorial headlines selectively.

Avoid making every section:

**HUGE TEXT + GIANT IMAGE + BUTTON**

Rhythm must vary.

# 13. 3D / WEBGL PHILOSOPHY

## 13.1 3D is an instrument, not an identity

Sweet Hill should not become "the 3D children's website."

Use 3D only when it improves:

- storytelling
- discovery
- product understanding
- emotional impact
- immersion

## 13.2 Three levels of 3D

### Level 1 — Micro 3D

- subtle depth
- rotation
- hover
- product movement

### Level 2 — Hero 3D

- cinematic environment
- object movement
- controlled camera
- scroll choreography

### Level 3 — Story-world 3D

- persistent canvas
- multiple scenes
- deeper narrative interaction

Version 1 should not automatically implement Level 3 everywhere.

```text
NAVIGATION
       ↓
HTML HERO CONTENT
       +
WEBGL / MOTION CANVAS
       ↓
TITLE
SUPPORTING COPY
CTA
       ↓
SCROLL
       ↓
CAMERA / SCENE MOVEMENT
       ↓
NEXT CONTENT SECTION
```

The HTML must remain meaningful without WebGL.

# 16. SCROLL PHILOSOPHY

Scrolling should sometimes be:

**navigation**

and sometimes:

**storytelling**

and sometimes:

**revelation**

and sometimes:

**product exploration**

Do not make every scroll event trigger something.

Motion must have rhythm.

# 17. MOTION SYSTEM

Motion should communicate:

**precision + calm + wonder**

## Use

- opacity fades
- scale changes
- masked reveals
- parallax
- controlled camera motion
- text choreography
- image transformations
- scene transitions
- subtle hover states

## Avoid

- bouncing
- constant movement
- gratuitous particles
- excessive cursor effects
- motion for every card
- perpetual animations
- accessibility-hostile motion

---

# 18. MOTION TIMING

Establish a consistent motion vocabulary.

Example working ranges:

- micro interaction: 120–240 ms
- interface transition: 240–500 ms
- editorial reveal: 500–1000 ms
- cinematic sequence: 1–4 s

These are starting values only.

Final values should be determined by prototyping.

---

# 19. SMOOTH SCROLL

Smooth scrolling may be used for specific cinematic experiences.

However:

- do not break native scrolling
- do not trap users inside a scroll section
- provide touch-friendly behaviour
- support reduced motion
- allow keyboard navigation
- prevent scroll hijacking from damaging usability

# 34. RESPONSIVE DESIGN

## Laptop

- preserve hierarchy
- reduce unnecessary effects

## Tablet

- recompose editorial sections
- simplify multi-column layouts

## Mobile

- prioritize content
- preserve visual identity
- use art-directed images
- simplify/disable advanced 3D when necessary
- maintain fast navigation
- maintain clear purchasing

# 36. REDUCED MOTION

# 38. PERFORMANCE BUDGET

The website's visual ambition must be constrained by performance.

Current Core Web Vitals guidance targets:

- LCP ≤ 2.5 s
- INP ≤ 200 ms
- CLS ≤ 0.1

at the 75th percentile.

Source:

https://web.dev/articles/vitals

Lab tools should be combined with real-user data.

Use:

- Lighthouse
- PageSpeed Insights
- WebPageTest
- Chrome DevTools
- field/RUM measurements when available

---

# 39. WEBGL PERFORMANCE RULES

Use the official MDN WebGL guidance as a baseline:

https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices

Pay particular attention to:

- texture compression
- mipmaps where appropriate
- draw-call reduction
- memory budgets
- reduced back-buffer resolution where appropriate
- shader cost
- GPU memory
- object disposal
- avoiding blocking calls
- adaptive rendering
- device pixel ratio management

The experience must not assume flagship desktop hardware.
